# LXC AutoScale API Documentation

**LXC AutoScale API** is a powerful, enterprise-grade RESTful interface designed to give you programmatic control over LXC containers hosted on a Proxmox server. With this API, you can automate and fine-tune various aspects of container management, including resource allocation, snapshots, and cloning.

## Security

The LXC AutoScale API includes multiple layers of security to protect your Proxmox infrastructure.

### API Key Authentication

All endpoints (except `/health/check` and `/metrics`) require authentication via API key.

**Configuration** (`lxc_autoscale_api.yaml`):
```yaml
authentication:
  enabled: true
  api_key: "your-secret-api-key-here"  # Change this!
```

**Usage**:
```bash
# Header-based authentication (recommended)
curl -H "X-API-Key: your-secret-api-key-here" \
  http://proxmox:5000/resource/vm/status?vm_id=104

# Query parameter authentication (fallback)
curl http://proxmox:5000/resource/vm/status?vm_id=104&api_key=your-secret-api-key-here
```

**Error Response** (401 Unauthorized):
```json
{
  "status": "error",
  "error": "Missing or invalid API key"
}
```

### Rate Limiting

Protects the API from abuse while allowing internal services unlimited access.

**Configuration** (`lxc_autoscale_api.yaml`):
```yaml
rate_limiting:
  enabled: true
  max_requests_per_minute: 120  # External clients
  time_window_seconds: 60
```

**Features**:
- **Localhost Bypass**: Requests from `127.0.0.1`, `::1`, or `localhost` are never rate limited
- **Per-IP Tracking**: Each client IP has its own request counter
- **Sliding Window**: 60-second rolling window for accurate rate limiting
- **Informative Headers**: Rate limit status in every response

**Response Headers**:
```
X-RateLimit-Limit: 120
X-RateLimit-Remaining: 45
X-RateLimit-Reset: 1703436789
```

**Error Response** (429 Too Many Requests):
```json
{
  "status": "error",
  "error": "Rate limit exceeded",
  "retry_after_seconds": 45,
  "limit": 120,
  "window_seconds": 60
}
```

**Headers**:
```
Retry-After: 45
X-RateLimit-Limit: 120
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1703436789
```

### Input Validation

All parameters are validated to prevent injection attacks and invalid operations.

**Validation Rules**:
- `vm_id`: Integer between 100 and 999999
- `cores`: Integer between 1 and 128
- `memory`: Integer between 64 (MB) and 1048576 (1TB)
- `disk_size`: Positive integer (GB)
- `snapshot_name`: Alphanumeric, underscore, hyphen (max 100 chars)
- `node_name`: Alphanumeric, hyphen, underscore (max 50 chars)

**Error Response** (400 Bad Request):
```json
{
  "status": "error",
  "error": "Invalid vm_id: must be between 100 and 999999"
}
```

## Routes

The LXC AutoScale API provides a range of endpoints that allow you to interact with your Proxmox host programmatically. Below is a comprehensive list of available routes, along with examples of how to use each one.

| Endpoint                    | Methods | Description                                                      | Example                                                                                               |
|-----------------------------|---------|------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------|
| `/scale/cores`              | POST    | Set the exact number of CPU cores for an LXC container.          | `curl -X POST http://proxmox:5000/scale/cores -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "cores": 4}'` |
| `/scale/ram`                | POST    | Set the exact amount of RAM for an LXC container.                | `curl -X POST http://proxmox:5000/scale/ram -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "memory": 4096}'` |
| `/scale/storage/increase`   | POST    | Increase the storage size of an LXC container's root filesystem. | `curl -X POST http://proxmox:5000/scale/storage/increase -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "disk_size": 2}'` |
| `/snapshot/create`          | POST    | Create a snapshot for an LXC container.                          | `curl -X POST http://proxmox:5000/snapshot/create -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "snapshot_name": "my_snapshot"}'` |
| `/snapshot/list`            | GET     | List all snapshots for an LXC container.                         | `curl -X GET "http://proxmox:5000/snapshot/list?vm_id=104" -H "X-API-Key: your-key"`                 |
| `/snapshot/rollback`        | POST    | Rollback to a specific snapshot.                                 | `curl -X POST http://proxmox:5000/snapshot/rollback -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "snapshot_name": "my_snapshot"}'` |
| `/clone/create`             | POST    | Clone an LXC container.                                          | `curl -X POST http://proxmox:5000/clone/create -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 104, "new_vm_id": 105, "new_vm_name": "cloned_container"}'` |
| `/clone/delete`             | DELETE  | Delete a cloned LXC container.                                   | `curl -X DELETE http://proxmox:5000/clone/delete -H "Content-Type: application/json" -H "X-API-Key: your-key" -d '{"vm_id": 105}'` |
| `/resource/vm/status`       | GET     | Check the resource allocation and usage for an LXC container.    | `curl -X GET "http://proxmox:5000/resource/vm/status?vm_id=104" -H "X-API-Key: your-key"`            |
| `/resource/vm/config`       | GET     | Get min/max resource limits for an LXC container.                | `curl -X GET "http://proxmox:5000/resource/vm/config?vm_id=104" -H "X-API-Key: your-key"`            |
| `/resource/node/status`     | GET     | Check the resource usage of a specific node.                     | `curl -X GET "http://proxmox:5000/resource/node/status?node_name=proxmox" -H "X-API-Key: your-key"`  |
| `/health/check`             | GET     | Perform a health check on the API server (no auth required).     | `curl -X GET http://proxmox:5000/health/check`                                                        |
| `/metrics`                  | GET     | Export Prometheus metrics (no auth required).                    | `curl -X GET http://proxmox:5000/metrics`                                                             |
| `/routes`                   | GET     | List all available routes.                                       | `curl -X GET http://proxmox:5000/routes -H "X-API-Key: your-key"`                                     |

### Detailed Descriptions

- **`/scale/cores`**: Allows you to set a specific number of CPU cores for a container. This is useful for adjusting resources based on the time of day or anticipated workload.
- **`/scale/ram`**: Lets you set the amount of RAM for a container. This can be used to allocate more memory during peak usage or reduce it during off-hours to save resources.
- **`/scale/storage/increase`**: Increases the storage size of the container’s root filesystem. This endpoint is particularly useful when a container’s storage requirements grow over time.
- **`/snapshot/create`**: Creates a snapshot of a container. Snapshots are essential for backup and recovery, allowing you to restore a container to a previous state if needed.
- **`/snapshot/list`**: Lists all snapshots for a given container. This endpoint helps you manage and review the available snapshots.
- **`/snapshot/rollback`**: Rolls back a container to a specific snapshot. Use this endpoint to revert changes made during the day or after testing new configurations.
- **`/clone/create`**: Clones a container, creating an exact copy under a new VM ID. This is ideal for testing or duplicating environments without affecting the original container.
- **`/clone/delete`**: Deletes a cloned container. This endpoint helps keep your environment clean by removing containers that are no longer needed.
- **`/resource/vm/status`**: Retrieves the current resource allocation and usage for a specific container, helping you monitor its performance.
- **`/resource/node/status`**: Provides an overview of the resource usage on a specific Proxmox node, allowing you to manage and optimize node performance.
- **`/health/check`**: Performs a health check on the API server to ensure it’s running correctly. This is useful for automated monitoring and alerting systems.
- **`/routes`**: Lists all available API routes, providing an overview of the endpoints you can interact with.

These routes offer a wide range of functionality, enabling comprehensive management of your LXC containers via simple HTTP requests.

## Prometheus Metrics

The API exports Prometheus-compatible metrics at the `/metrics` endpoint for comprehensive monitoring and alerting.

### Available Metrics

**Scaling Actions**:
```
lxc_scaling_actions_total{container_id="104",action="scale_up",resource="cpu"} 15
lxc_scaling_actions_total{container_id="104",action="scale_down",resource="ram"} 8
```

**API Requests**:
```
lxc_api_requests_total{endpoint="/scale/cores",method="POST",status="200"} 42
lxc_api_request_duration_seconds{endpoint="/scale/cores"} 0.125
```

**Container Resources**:
```
lxc_container_cpu_cores{container_id="104"} 4
lxc_container_memory_mb{container_id="104"} 8192
lxc_container_cpu_usage_percent{container_id="104"} 65.2
lxc_container_memory_usage_percent{container_id="104"} 78.5
```

**Circuit Breaker**:
```
lxc_circuit_breaker_state{endpoint="api_104"} 0  # 0=closed, 1=open
lxc_circuit_breaker_failures{endpoint="api_104"} 2
```

**Model Predictions**:
```
lxc_model_predictions_total{container_id="104",prediction="normal"} 120
lxc_model_predictions_total{container_id="105",prediction="anomaly"} 5
```

### Prometheus Configuration

Add this to your `prometheus.yml`:

```yaml
scrape_configs:
  - job_name: 'lxc_autoscale_api'
    static_configs:
      - targets: ['proxmox:5000']
    metrics_path: '/metrics'
    scrape_interval: 30s
```

### Example Grafana Queries

**Scaling Rate (per hour)**:
```promql
rate(lxc_scaling_actions_total[1h]) * 3600
```

**Scale Up vs Scale Down Ratio**:
```promql
sum(lxc_scaling_actions_total{action="scale_up"}) / sum(lxc_scaling_actions_total{action="scale_down"})
```

**Average API Response Time**:
```promql
rate(lxc_api_request_duration_seconds_sum[5m]) / rate(lxc_api_request_duration_seconds_count[5m])
```

**Containers with High CPU Usage**:
```promql
lxc_container_cpu_usage_percent > 80
```

**Circuit Breaker Open Count**:
```promql
count(lxc_circuit_breaker_state == 1)
```

## Logs

Logging is a critical component of managing and troubleshooting the LXC AutoScale API. The service generates several log files that provide detailed information about its operations.

### Log Files

- **`/var/log/autoscaleapi.log`**: The main log file for the API, containing detailed information about API requests, responses, and any internal processing.
- **`/var/log/autoscaleapi_access.log`**: Logs all incoming requests to the API, including timestamps, request methods, endpoints accessed, and the source IP addresses. This log is essential for monitoring API usage and identifying potential security issues.
- **`/var/log/autoscaleapi_error.log`**: Captures errors encountered by the API service. Reviewing this log can help diagnose issues and ensure that the API runs smoothly.

### Log Management

Regularly review these logs to monitor the health and performance of the API service. Consider implementing log rotation to manage disk space, especially in environments with high API traffic. You can use tools like `logrotate` to automate the rotation, compression, and removal of old log files.

Example `logrotate` configuration:

```bash
/var/log/autoscaleapi*.log {
    daily
    missingok
    rotate 7
    compress
    delaycompress
    notifempty
    create 640 root adm
    sharedscripts
    postrotate
        systemctl reload lxc_autoscale_api.service > /dev/null 2>&1 || true
    endscript
}
```

This configuration rotates the log files daily, keeps seven days of logs, compresses old logs, and ensures the service continues to operate without interruption.

## Best Practices and Tips

### 1. Secure Your API

The API now includes built-in security features:

- **API Key Authentication**: Already enabled by default. Change the default key in `lxc_autoscale_api.yaml`
- **Rate Limiting**: Protects against abuse. Localhost is exempt for internal services.
- **Input Validation**: All parameters are validated automatically.
- **Use a Firewall**: Still recommended - restrict access to trusted IP addresses.
- **Enable HTTPS**: Use a reverse proxy like Nginx or Apache to handle SSL/TLS encryption.

**Example Nginx HTTPS Proxy**:
```nginx
server {
    listen 443 ssl;
    server_name proxmox-api.example.com;
    
    ssl_certificate /etc/ssl/certs/proxmox-api.crt;
    ssl_certificate_key /etc/ssl/private/proxmox-api.key;
    
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### 2. Monitor API Usage

Multiple monitoring options are now available:

- **Access Logs**: Monitor `autoscaleapi_access.log` for all API requests
- **Error Logs**: Check `autoscaleapi_error.log` for issues
- **Prometheus Metrics**: Use the `/metrics` endpoint for real-time monitoring
- **Rate Limit Headers**: Check `X-RateLimit-Remaining` in API responses

**Quick Usage Stats**:
```bash
# Total requests today
grep "$(date +%Y-%m-%d)" /var/log/autoscaleapi_access.log | wc -l

# Top 10 IP addresses
grep "$(date +%Y-%m-%d)" /var/log/autoscaleapi_access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# Error rate
grep "429\|500\|401" /var/log/autoscaleapi_access.log | wc -l
```

### 3. Automate Routine Tasks

Use cron jobs in combination with API requests to automate routine tasks such as scaling resources or creating snapshots. This reduces manual intervention and helps maintain optimal performance.

### 4. Test Before Production

When implementing new API routes or making changes to existing ones, always test in a non-production environment first. This helps ensure that the commands work as expected without disrupting live services.

### 5. Document Your API Usage

Maintain documentation of how your environment interacts with the LXC AutoScale API, including the routes used, the purpose of each request, and any scripts or automation tools that rely on the API. This documentation is invaluable for troubleshooting and for onboarding new team members.
